## 1. Rollout 稳定性：最重要的负面结果

### 1.1 协议

把学到的**一步生成器**反复应用 $k$ 次，与**物理模拟器**跑 $k\times T$ 的真值比较。
所有比较用同一初值云、同一 $k$、同一套精确 OT。

- 粒子数 20,000（模拟器 $O(N^2)$，100k 会慢 25 倍）
- 打分用 3,000 粒子子样本（精确 OT，POT network simplex）
- 底噪（两次独立物理模拟之差）：**0.1573**（同 $n=3000$ 口径）

### 1.3 判读：三层结论

**① $k=1$ 是唯一可用的工作点。**
所有格点上 $W_2/\text{底噪}$ 在 0.59–1.55 之间，即模型在单步上与两次独立物理模拟的差异同量级。**这与主结论一致。**

**② $k=2$ 已经开始发散，$k\ge4$ 完全崩溃。**
$W_2$ 从 0.09–0.24 跳到 0.20–4.6，再跳到 4.5–82。**RMS 半径从 0.84 涨到 26,000** —— 云在物理上被拉爆了，不是度量伪影。

**③ 每一步的位移量超过物理真值的 1.5–4,000 倍。**
定义放大因子

$$
\text{amp}(k)=\frac{W_2(\text{云}_{k},\text{云}_{k-1})}{W_2(\text{物理}_{k},\text{物理}_{k-1})}
$$

物理每步只移动 0.17–0.54（$\sigma$ 大时更大），而模型每步移动 0.27 → 41,597。**amp 从 1.5 涨到 4,042。**

### 1.4 为什么必然发散（机制）

训练时输入分布是 $\mu_0$（单位球均匀）。推理一次后，输出云的位置已完全不同于 $\mu_0$：
质心从 0 移到 1.3–2.3，RMS 半径 0.84–1.57。**把这样的云再喂给网络，它落在训练分布之外，输出无意义。**

所以 **rollout 不是"模型的长期行为"，而是"分布外推"。** 这不是本方法的特定缺陷——任何"学一个固定时间步长的流映射"的模型都不能直接迭代。

> **对 Harry 的诚实回答**：我们的方法**不是**时间步进器，不能替代数值积分。
> 它是"给定初值，一次跳到 $T$"。若要长时程，必须**重训一个 $T$ 更大的模型**，而不是迭代。

## 2. DP 是否让稳定性变差？——否，但两步 MF 会

这是 Harry 的关键一问：*"show whether the corrector improves typical cases but introduces a small number of unstable rollouts"*。

三个映射，**每次应用都是 2 次前向**（成本匹配）：

| 映射 | 构成 |
|---|---|
| `mf` | 冻结 MF 应用两次 |
| `mf_dp` | MF 一次 + DP 一次 |
| `mf_2step` | 冻结 MF 按 $(r,t)=(0.5,1),(0,0.5)$ 两段应用 |

### 2.1 结果

| 格点 | 方法 | $k$ | $W_2$ vs 物理 | /底噪 | **amp** | RMS 半径 |
|---|---|---:|---:|---:|---:|---:|
| s03_m04 | mf | 1 | 0.1167 | 0.74 | — | 0.875 |
| | mf | 2 | 1.2561 | 7.99 | 3.06 | 1.927 |
| | mf | 4 | 16.916 | 107.5 | 17.05 | 16.54 |
| | **mf_dp** | 1 | **0.1119** | **0.71** | — | 0.874 |
| | **mf_dp** | 2 | **1.1912** | **7.57** | **2.95** | 1.884 |
| | **mf_dp** | 4 | **15.677** | **99.7** | **15.81** | 15.51 |
| | mf_2step | 1 | 0.1168 | 0.74 | — | 0.880 |
| | mf_2step | 2 | 1.5541 | 9.88 | 3.59 | 2.184 |
| | mf_2step | 4 | **44.656** | **283.9** | **45.57** | 41.12 |
| s09_m06 | mf | 4 | 35.964 | 228.6 | 15.51 | 30.27 |

### 2.2 结论

**① DP 让 $k=1$ 更好（一致性检查）**：0.1167→0.1119、0.1396→0.1340、0.2480→0.2439。

**② DP 让 $k\ge2$ 也略好，不是略差**：
- $k=4$：15.68 vs 16.92（s03）、33.36 vs 35.96（s09）、77.21 vs 82.52（s19）
- amp 也略低：15.81 vs 17.05、14.36 vs 15.51、28.50 vs 30.45

**③ 两步 MF 最差，差一个量级**：$k=4$ 时 44.7 / 118.2 / 317.7，比 MF 和 MF+DP 都差得多。

> **这个结果直接回答 Harry 的担忧**：DP **没有**引入不稳定 rollout，它甚至略微改善了外推稳定性。
> 而"多走几步"（两步 MF）确实显著恶化——**这反而证明了"加修正器"优于"多加一步"**。

**④ 但必须说清**：所有方法在 $k\ge2$ 都发散。**DP 只是把发散推迟了一点点，没有解决它。**

### 3.4 判读

**① 模型抓住了正确的物理。** 所有量的相对误差都在 **0.6%–4%**，远小于 $W_2$ 暗示的偏差。特别是 **各向异性比误差 < 1%** —— 这说明模型学到的不是"形状碰巧接近"，而是**正确的剪切-扩散平衡**。

**④ 必须修正一处**：`centroid_y`/`centroid_z` 的"相对误差 7.47"是**伪影**。这两个量按对称性接近 0（量级 $10^{-2}$），除以它们会爆炸。正确的统计是**绝对偏差**：MF 均值 $6.4\times10^{-3}$（$y$）、$1.7\times10^{-2}$（$z$）；MF+DP 为 $5.8\times10^{-3}$、$1.2\times10^{-2}$。相对云尺度（1.5）即 **1%**。

## 4. $\alpha$ 在开发集上选、测试集上报

### 4.1 协议

Harry 明确要求 *"choose any correction-strength settings on development cases, not the final evaluation set"*。

**划分**（固定种子 424242，已存档 `results/fullscale/alpha_sweep/split.json`）：

| 划分 | 格数 | 用途 |
|---|---:|---|
| 训练 | 40 | 训练 MF 与 DP（固定）|
| **dev** | **50** | **只用来选 $\alpha$** |
| **test** | **94** | **$\alpha$ 选定后才动，只报数** |

**$\alpha$ 的含义**：修正器输出层零初始化，形式为 $x+\alpha\cdot\text{MLP}(x)$。所以 $\alpha$ 是**部署时的旋钮**（不是重训）。这一点必须说清：本实验扫的是推理时缩放，不是每个 $\alpha$ 重训一次。

### 4.2 dev 上的扫描

| $\alpha$ | dev 平均 $W_2$ |
|---:|---:|
| 0.00（= MF 单独）| 0.12338 |
| 0.25 | 0.11850 |
| 0.50 | 0.11370 |
| 0.75 | 0.10918 |
| **1.00（上游默认）** | 0.10505 |
| 1.50 | 0.09864 |
| **2.00** | **0.09689** ← 选中 |
| 3.00 | 0.10886 |
| 4.00 | 0.12969 |

**dev 上最优是 $\alpha=2$，不是上游默认的 $\alpha=1$。**

### 4.3 test 上的验证（未参与选参）

| 配置 | test 平均 $W_2$ | 相对 MF |
|---|---:|---:|
| MF 单独 | 0.12156 | — |
| $\alpha=1.0$ | 0.10308 | **+15.2%** |
| $\alpha=2.0$ | **0.09422** | **+22.5%** |

### 4.4 结论

**① $\alpha=2$ 比 $\alpha=1$ 好，且在未见过的 test 上复现。** 从 +15.2% 提升到 **+22.5%**。

**② 上游默认 $\alpha=1$ 是保守的（欠修正）。** dev 曲线上 1.5→2.0 仍在下降，2.0 之后才回升，说明最优在 2 附近。

**③ 但这是一个新发现，需要谨慎**：dev 只有 50 格，曲线在 1.5–2.0 之间较平（0.0986 vs 0.0969），差异可能部分来自划分噪声。**若要写进论文，建议在多个 dev 划分上重复。**

> **对 Harry 的价值**：这正好演示了他要求的纪律——**先在 dev 上选，再在 test 上报**。而且结果是"上游默认值不是最优"，这本身是一个可复现的小贡献。

## 5. 四项对照（Harry 的原话）

他要的是：*(a) the global map alone, (b) the map plus your corrector, (c) a capacity-matched predictor, and (d) a few-step flow baseline under comparable measured inference cost.*

### 5.1 结果（144 留出格，16 箱精确 OT）

| 配置 | $W_2$ | sd | 前向次数 | 参数量 |
|---|---:|---:|---:|---:|
| **(a) MF 一步** | 0.12219 | 0.04655 | **1** | 9,027 |
| **(b) MF + DP，$\alpha{=}1$** | 0.10376 | 0.04226 | 2 | 26,502 |
| **(b') MF + DP，$\alpha{=}2$** | **0.09515** | 0.04045 | 2 | 26,502 |
| **(d) MF 两步**（同权重）| 0.12332 | 0.04838 | 2 | 9,027 |

### 5.2 关键判读

**① 成本匹配下，(d) 两步 MF 毫无收益**：0.12332 vs 一步 0.12219，**略差**。
**而 (b) 同成本下改善 24%（相对 (a)）。**

> **这是 DP 存在价值的最直接证据**：同样是 2 次前向，"多加一步"没用，"加一个修正器"有用。

**② (c) 容量匹配**：见 §6。宽度 112 的单一网络有 **26,547 参数**，与 MF+DP 的 26,502 只差 **0.17%**。

### 5.3 训练时 OT 成本（Harry 特别问的）

DP 阶段的 OT 开销：

| 项 | 值 |
|---|---|
| OT 类型 | POT network simplex（精确，非 Sinkhorn）|
| batch 大小 | 2,000 |
| 刷新频率 | 每 **10** 步一次 |
| 每格 OT 次数 | 2000 / 10 = **200** |
| 40 格总次数 | **8,000** |
| 单次耗时（$n{=}3000$ 实测）| 0.18 s → $n{=}2000$ 约 0.08 s |
| **OT 总耗时** | 约 **11 分钟** |
| DP 总训练时间 | 9,435 s = **157 分钟** |
| **OT 占比** | **约 7%** |

**所以正确的说法是**：

> 我们在**训练时**需要 minibatch OT（占总训练时间约 7%），**部署时完全不需要 OT**。
> "避免全局 OT"不等于"消除所有 OT"——Harry 的这个提醒是对的，我们的 7% 就是那部分代价。

### 6.2 状态

结果写入 `results/fullscale/capacity_matched/capacity_matched.json`。

### 6.3 若 (c) 与 (b) 持平意味着什么

如果 26,547 参数的单一网络达到 0.095–0.104，则**DP 的收益可被容量解释**，方法的核心卖点就倒了。

若 (c) 明显差于 (b)（例如 ≥0.115），则证明**"分成两个网络"本身有价值**，而不只是参数多。

**仓库已有的间接证据**（单参数设定，`DESIGN_CRITERION.md` §5.5）：参数量从 9,027 增到 134,403（**15 倍**）**没有任何改善**，甚至 128 宽稳定略差（0.1561 vs 0.1486）。这强烈暗示 (c) 不会赢，但**必须在双参数、同预算下直接测**才算证据。
