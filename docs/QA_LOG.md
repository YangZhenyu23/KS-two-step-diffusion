> （3）一共生成了哪些粒子云？训练数据集有哪些、分别什么格式？
> （4）训练时用了什么？评测时又用了哪些？如何调用？

### A1.1 对理解的第一处核对：基本正确，但有两处需澄清

**正确的部分**：

- ✅ **粒子交互法**：`simulate_original` 求解的是 $N$ 个相互作用粒子的随机微分方程。
- ✅ **从均匀分布出发**：初值在单位球内均匀抽样。实现用 $r^{1/3}$ 变换保证球内均匀（`unit_ball`，`fullscale/generate.py:56`）。
- ✅ **通过 SDE 动力学到达目标分布**：跑 4 个时间步后取终态。

**需要澄清的第一点：方程不是"KS 方程"，而是 KS 的粒子系统**

代码实际求解的（`upstream/MF-DeepParticle/deepparticle/training/protocol.py:40`）：

$$
dX_j = -\frac{\chi}{N}\sum_{i\neq j}\nabla K_\delta(X_j-X_i)\,dt
\;+\;\sigma\,g(X_j)\,dt
\;+\;\sqrt{2\mu}\,dW_j,
$$

其中 $g(x)=(e^{-y^2-z^2},0,0)$，$K_\delta(z)=\lvert z\rvert/\big(4\pi(\lvert z\rvert^2+\delta^2)\big)$。

三项分别是**趋化相互作用**（$O(N^2)$）、**剪切流**、**布朗扩散**。这是 KS 偏微分方程的粒子离散，不是 PDE 本身。

**需要澄清的第二点："运输"不是最优传输意义下的映射**

这里没有求解 Monge/Brenier 最优映射。严格说法是**推前测度**：初值分布 $\mu_0$ 被 SDE 的随机流 $\Phi$ 推前成终态分布 $\nu=\Phi_\#\mu_0$。"运输"是直觉描述，不是最优传输的术语。

（顺带：最优传输只在**评测**时出现，用于计算两团云之间的 $W_2$。）

**数值格式**：4 步 Euler–Maruyama，$dt=0.005$，$T=0.02$；`points += dt*force + sqrt(2*mu*dt)*noise`。浮点用 float64 计算、float32 存储。

### A1.2 粒子云的数学形式

**数学上是一组加权 Dirac 测度**：

$$
\hat\mu_N=\frac{1}{N}\sum_{i=1}^N\delta_{X_i},\qquad X_i\in\mathbb{R}^3,\ N=10^5 .
$$

所有粒子**等权** $1/N$，没有额外权重。

**磁盘上**每格一个 `.npz`（`np.savez_compressed`），含 **4 个字段**：

| 键 | 形状 | 类型 | 含义 |
|---|---|---|---|
| `meta` | 标量字符串 | — | JSON：σ、μ、粒子数、噪声种子、初值 SHA256、耗时、无量纲数 |
| `initial` | (100000, 3) | float32 | 单位球初值云 |
| `source` | (100000, 3) | float32 | **与 `initial` 逐元素相同** |
| `reference` | (100000, 3) | float32 | 物理真值（终态云）|

`initial` 与 `source` 内容重复，是刻意的：为了让文件与上游 `ks_cloud_v1` 格式兼容。上游协议中 MeanFlow 总从新抽的单位球出发，故"待输运的云"即初值本身。

**路径布局**：

```
results/fullscale/data/full/
├── initial.npy                共享初值 (100000,3)，独立一份
├── manifest.json              200 格清单，每格含 file / sha256 / bytes / 参数 / 耗时
└── clouds/
    └── s{ii}_m{jj}.npz        共 200 个，ii=σ索引, jj=μ索引
```

命名示例：`s09_m05` 对应 $\sigma=100$（第 10 个 σ）、$\mu=1.0$（第 6 个 μ）。

### A1.4 训练时使用了什么

#### 加载代码（`fullscale/train.py` 的 `load_training_tensors`）

```python
initial = None
targets = []
for cell in cells:                              # 40 个 LHS 选出的格点
    payload = load_cell(cell)
    start  = payload["clouds"]["initial"]       # 只读 initial
    target = payload["clouds"]["reference"]     # 只读 reference
    if initial is None:
        initial = start
    elif not np.array_equal(initial, start):
        raise ValueError("cells do not share one initial cloud")   # 强制校验共享初值
    targets.append(target)

return (torch.from_numpy(initial).to(device),                   # (100000, 3)
        torch.from_numpy(np.stack(targets)).to(device))         # (40, 100000, 3)
```

**训练只使用 `initial` 与 `reference` 两个字段。**

`source` 在训练中**完全未使用**。

#### 显存布局

| 张量 | 形状 | 大小 |
|---|---|---|
| `initial` | (100000, 3) | 1.2 MB |
| `targets` | (40, 100000, 3) | 48 MB |

合计约 96 MB（含副本），全部常驻显存。

#### 每步取数

```python
env = torch.randint(len(cells), (1,)).expand(batch_size)   # 随机选一格
idx = torch.randint(N, (batch_size,))                      # 随机选粒子
x_target = targets[env, idx]     # (4096, 3)
x_source = initial[idx]          # (4096, 3)  ← 对任何 env 都相同
```

**关键点**：`initial[idx]` 与 `env` 无关，正是"共享初值"设计在训练中的体现。

#### 训练目标（与云的格式无关）

$$
\mathcal{L}=\mathbb{E}\Big\|u_\theta(z,r,t,c)-\big(v-(t-r)\tfrac{d}{dt}u_\theta(z,r,t,c)\big)\Big\|^2,
$$

其中 $v=x_{\text{source}}-x_{\text{target}}$，$z=(1-t)x_{\text{target}}+t\,x_{\text{source}}$，$c=(\log_{10}\sigma,\log_{10}\mu)$。

**逐粒子的均方误差，不涉及任何直方图或 OT。**

### A1.5 评测时使用了什么

#### 主实验（143 个留出格）

```python
payload   = load_cell(cell)
source    = payload["clouds"]["source"]       # 推理输入

# 或 exact_w2(prediction[idx], reference[idx])      # 粒子级口径（3000 点子样本）
```

因为 `source ≡ initial`，**200 个格点推理时喂的是同一团初值云**，仅条件 $(\sigma,\mu)$ 不同。

#### 三种评测的字段使用对照

| 评测类型 | 读 `source` | 读 `reference` | 是否需新模拟 |
|---|---|---|---|
| 主实验（模型 vs 真值）| ✅ 作推理输入 | ✅ 作真值 | ❌ |
| 底噪（真值 vs 真值）| ❌ | ✅ 作第一个样本 | ✅ 需第二条独立云 |
| 粒子级重测 | ✅ | ✅ | ❌（复用 5 点底噪）|

评测时用 `shared_edges([reference, prediction])` 为**每一格单独**构建 16 箱网格。若用全局网格，箱宽由整个参数域跨度决定，$W_2$ 会虚高约 4 倍（早期实现的缺陷，已修正）。

### A1.6 一句话总结

| 环节 | 内容 |
|---|---|
| **生成** | 单位球均匀初值 → SDE 走 4 步 → 终态云（推前测度）|
| **保存** | 每格一个 `.npz`，4 字段：`meta` / `initial` / `source` / `reference`，float32 |
| **训练** | 只用 `initial`（共享，1.2 MB）+ `reference`（每格一份，48 MB 共 40 格），随机抽 4096 粒子，MSE 损失 |
| **评测** | 用 `source`（≡initial）作输入、`reference` 作真值，评分函数可换（直方图 / 粒子级）|

**训练与评测的耦合点只有一个：评测读取训练好的 checkpoint。云数据本身在两边独立使用。**

### A2.1 $W_2$ 算的是什么：理解正确

用户的表述是对的：

$$
(\sigma,\mu)\ \xrightarrow{\text{MeanFlow 一次前向}}\ \hat\nu_{\text{model}}
\quad\text{对比}\quad
\hat\mu_{\text{ref}},
$$

$$
\text{metric}=W_2(\hat\nu_{\text{model}},\hat\mu_{\text{ref}}).
$$

**一个容易误解的点**：网络输入的种子云（`source`）**不参与** $W_2$。它只是推理起点：

```
source（初值）──网络──> model_output ─┐
                                       ├─> W2
reference（真值）───────────────────────┘
```

#### 数学定义

$$
W_2(\mu,\nu)=\left(\inf_{\gamma\in\Gamma(\mu,\nu)}\int\|x-y\|^2\,d\gamma\right)^{1/2},
$$

$\Gamma(\mu,\nu)$ 为以 $\mu,\nu$ 为边缘的联合分布全体。对两组等权点云 $P,Q$（各 $N$ 点），$\gamma$ 退化为双随机矩阵，问题成为线性规划：

$$
\min_{\gamma\ge0}\sum_{ij}\gamma_{ij}\|p_i-q_j\|^2
\quad\text{s.t.}\quad \sum_j\gamma_{ij}=\tfrac1N,\ \sum_i\gamma_{ij}=\tfrac1N .
$$

代码用 POT 的 network simplex（`ot.emd2`）精确求解，并强制三项证书：求解器报告最优、边际残差 $<10^{-9}$、对偶间隙 $<10^{-8}$（`fullscale/evaluate.py:52`）。

---

### A2.2 两种口径的区别：只在"支撑点是什么"

两者都算 $W_2$，差别在于**测度的支撑点与权重从哪里来**。

#### 口径 A：16 箱直方图

**第一步，建共享网格**（`shared_edges`，`evaluate.py:32`）：

```python
stacked = np.concatenate([reference, prediction])
lo, hi = stacked.min(axis=0), stacked.max(axis=0)
edges = [np.linspace(lo[d]-pad, hi[d]+pad, bins+1) for d in range(3)]
```

每轴 16 箱，网格最多 $16^3=4096$ 个箱。

**第二步，压成箱计数**（`measure`，`evaluate.py:41`）：

```python
counts, _ = np.histogramdd(points, bins=edges)
index = np.argwhere(counts > 0)
positions = 箱中心坐标
weights   = counts / N
```

**十万个粒子被压成至多 4096 个"箱中心 + 权重"。**

**第三步，在箱中心上解 OT**：

$$
W_2^{\text{hist}}=\Big(\min_\gamma\sum_{ij}\gamma_{ij}\|c_i-c_j\|^2\Big)^{1/2},
$$

$c_i$ 为箱中心，$\gamma$ 的边际为箱权重。

**丢失的信息**：箱内粒子的具体位置。

#### 口径 B：粒子级

```python
def exact_w2(a, b):
    cost = cdist(a, b, metric="sqeuclidean")   # 粒子两两距离
    w = np.full(n, 1.0/n)                      # 等权
    value = ot.emd2(w, w, cost)
    return sqrt(value)
```

**不建网格、不压箱，直接在粒子坐标上解精确 OT。**

**必须子采样**：10 万粒子的代价矩阵约 400 GB。取 $m=3000$，代价矩阵约 72 MB。

**配对抽样**：误差与底噪用同一索引向量，避免抽样差异污染比较。

#### 对照表

| | 直方图 | 粒子级 |
|---|---|---|
| 支撑点 | 箱中心（$\le4096$）| 粒子坐标（3000）|
| 权重 | 箱内粒子数占比 | 全部等权 $1/m$ |
| 丢失信息 | **箱内位置** | 无（但在子样本上）|
| 单次耗时 | ~0.2 s | ~1 s |
| 能否处理 10 万点 | ✅（先压箱）| ❌（必须子采样）|
| **底噪** | 0.045 | 0.090 |
| **底噪中量化占比** | **94%** | ~0% |

### A2.3 底噪为什么存在

#### 本质：$W_2$ 作用于**经验测度**

参考云不是真分布 $\mu$，而是它的一次有限抽样：

$$
\hat\mu_A=\frac1N\sum_{i=1}^N\delta_{X_i},\qquad X_i\overset{iid}{\sim}\mu .
$$

**即使模型完美学到 $\mu$**，它输出的是另一次独立抽样，两者 $W_2$ **仍不为零**。

**底噪 = 同一分布两个独立有限样本之间的距离。**

#### 量级

由三角不等式，

$$
W_2(\hat\mu_A,\hat\nu)\le\underbrace{W_2(\hat\mu_A,\mu)}_{\varepsilon_N}+\underbrace{W_2(\mu,\hat\nu)}_{\varepsilon_N}\lesssim2\varepsilon_N,
$$

Fournier–Guillin（$d=3$）：$\varepsilon_N\sim N^{-1/3}$。$N=10^5$ 时 $\varepsilon_N\approx0.046$，乘 2 得 $\approx0.09$。

**底噪减半需 $N$ 增 8 倍**（三维的代价）。

#### 四个来源

| 来源 | 量级 | 能否消除 |
|---|---|---|
| 粒子数有限 | $O(N^{-1/3})$ | 加 $N$（8 倍才减半）|
| **直方图量化** | $O(\Delta)$ | **加箱数** |
| 物理噪声流（布朗路径）| — | **不能** |
| 初值抽样 | — | **不能** |

#### 如何测量

同一参数点跑 $R$ 条**完全独立**的模拟（不同初值种子、不同噪声种子），两两配对求 $W_2$ 后取均值：

$$
\hat\varepsilon=\frac{1}{\binom{R}{2}}\sum_{p<q}W_2(\text{cloud}_p,\text{cloud}_q).
$$

**必须用独立初值**：若共用初值，"初值抽样差异"被人为消除，底噪会偏小。

#### 决定性检验：量化占 94%

保持粒子位置不变，仅按其箱计数的多项分布**重抽**箱内分配。两团"云"物理上完全相同，其 $W_2$ 即纯量化噪声：

| 箱数 | 直方图底噪 | 纯量化噪声 | 占比 |
|---:|---:|---:|---:|
| 12 | 0.0478 | 0.0466 | 97% |
| **16** | **0.0455** | **0.0428** | **94%** |
| 24 | 0.0418 | 0.0385 | 92% |
| 32 | 0.0394 | 0.0349 | 89% |

### A2.4 测得误差如何分解为两部分

#### 分解

设 $\hat\nu$ 为模型输出（确定性映射，**无自身抽样噪声**）、$\hat\mu_A$ 为参考云、$\mu$ 为真分布。目标是 $W_2(\hat\nu,\mu)$，实际测得 $W_2(\hat\nu,\hat\mu_A)$。由三角不等式：

$$
\boxed{
\underbrace{W_2(\hat\nu,\hat\mu_A)}_{\text{测得}}
=
\underbrace{W_2(\hat\nu,\mu)}_{\text{模型误差}}
+
\underbrace{\varepsilon}_{\text{底噪，不可消除}}
}
$$

#### 但不能简单相减

直觉上想用勾股 $E^2=E_{\text{true}}^2+\varepsilon^2$。**这不成立**：$(\mathcal P_2,W_2)$ 是 Alexandrov 空间（曲率下界 0），不是希尔伯特空间；勾股仅在**一维**或**高斯**情形成立。

**只能给区间**：

$$
\underbrace{E-\varepsilon}_{\text{悲观}}\ \le\ E_{\text{true}}\ \le\ \underbrace{E}_{\text{平凡上界}} .
$$

若额外假设两者正交，可用 $E_{\text{true}}\approx\sqrt{\max(E^2-\varepsilon^2,0)}$（乐观）。

#### 实测：比值接近 1

同一模型、同一格点（$\sigma=100,\mu=1$）：

| 口径 | 模型误差 $E$ | 底噪 $\varepsilon$ | 比值 $E/\varepsilon$ |
|---|---:|---:|---:|
| 直方图 16 箱 | 0.0647 | 0.0455 | **1.44** |
| **粒子级 3000 点** | **0.0857** | **0.0904** | **0.95** |

**同一模型，两种口径给出截然不同的"离极限多远"判断**：直方图说"还差 44%"，粒子级说"已到极限"。

原因是直方图底噪被量化撑大 94%，而模型误差本身很小，比值因而显得大。

#### 比值可略小于 1 的原因

| | 独立抽样噪声 |
|---|---|
| 参考云 $\hat\mu_A$ | 一份 |
| 第二个真样本 $\hat\mu_B$ | **另有一份（独立）** |
| **模型输出 $\hat\nu$** | **没有新的** |

模型是确定性映射，故可比"另一个真样本"更接近参考云。启发式上完美模型的比值趋于

$$
\frac{W_2(\hat\mu_A,\hat\nu)}{W_2(\hat\mu_A,\hat\mu_B)}
\approx\frac{\varepsilon_N}{\sqrt2\,\varepsilon_N}=\frac{1}{\sqrt2}\approx0.71 .
$$

（严格限定：$W_2$ 无勾股关系，此式仅为启发式，只能说比值落在 $[0.71,1]$。）

实测 5 个参数点均值 **1.04**（范围 0.95–1.11），落在该区间内。

## Q3. 直方图与粒子级的选择依据；全量计算会否降低 $W_2$；可行的采样方案

### 提问

> （1）底噪是因为经验测度随机抽取导致，不可能完全消除，对吗？
> （2）直方图是不是因为粒子数极大时显存/内存不够，先压成方框、忽略箱内性质以降低开销？
> （3）只要"模型误差 / 底噪"的比值接近 1，就说明模型学到了所有性质，只是底噪去不掉，对吗？
> （4）直方图是不是处理"粒子数过多"的好方式？
> （5）如果粒子级不做抽样、全量计算，$W_2$ 损失会不会更小？
> （6）若全量做不到（内存最多 32 GB），是否有已有结论支持某些特定采样方式？

### A3.1 用户理解的三处核对

#### ✅ 正确：底噪源于经验测度，不可完全消除

由 $W_2$ 作用于经验测度，抽样误差量级为

$$
\varepsilon_N\sim N^{-1/3}\quad(d=3),
$$

只能通过增加 $N$ 或箱数**减小**，不能消除。$N\to\infty$ 不可行。

#### ⚠️ 修正一：直方图的主要动机是**降复杂度**，不只是省内存

$W_2$ 的精确计算需要 $O(N^2)$ 代价矩阵与 $O(N^3)$ 网络单纯形。直方图把支撑点数从 $N$ 降到"非空箱数"，这是**降低复杂度**：

| | 直方图 | 粒子级 |
|---|---|---|
| 支撑点数 | $\le B^{3}=4096$（$B{=}16$）| $m$ |
| OT 复杂度 | $O(B^{9})$ | $O(m^3)$ |
| 10 万粒子 | ✅ 先压箱 | ❌ 代价矩阵 74.5 GiB |

**另一个更根本的动机**：直方图是上游论文的口径，用它才能与文献比较。

#### ⚠️ 修正二：比值接近 1 的正确含义

比值含义为

$$
\rho=\frac{W_2(\hat\nu,\hat\mu_A)}{W_2(\hat\mu_A,\hat\mu_B)},
$$

其中 $\hat\mu_B$ 为同参数的另一个独立真样本。

- $\rho=1$：模型精度**等于两次物理模拟之间的差异**
- $\rho<1$（理论上可到 $0.71$）：模型比"另一个真样本"更接近参考
- $\rho>1$：模型有额外误差

"学到所有性质"的说法不够准确：模型学到的是**分布**，不可能重现参考云的某次噪声实现。$\rho=1$ 表示"分布学对了"，而非"重现了某次抽样"。

#### ⚠️ 修正三：此前关于代价矩阵体积的口误

曾称 10 万粒子的代价矩阵约 400 GB，**有误**。正确数值：

| $N$ | float64 | float32 |
|---:|---:|---:|
| 3,000 | 0.07 GiB | 0.03 GiB |
| 10,000 | 0.75 GiB | 0.37 GiB |
| 30,000 | 6.71 GiB | 3.35 GiB |
| **100,000** | **74.5 GiB** | **37.3 GiB** |

即 **74.5 GiB**（float64），不是 400 GB。

---

### A3.2 直方图是否是好办法

**是该场景下的合理选择，但不是最优。**

#### 复杂度对照

| 方案 | 复杂度 | 代价 |
|---|---|---|
| **直方图** | $O(B^{3d})$ | 量化误差；16 箱时**占底噪 94%** |
| 子采样 | $O(m^3)$ | 抽样误差，$m$ 小时偏差大 |
| **Sinkhorn（熵正则）** | $O(N^2/\varepsilon^2)$，GPU 可并行 | 近似偏差，需报告 $\varepsilon$ |
| Sliced $W_2$ | $O(P\cdot N\log N)$ | **不是 $W_2$**，只是下界 |
| Multiscale OT | $O(K^3+NK)$ | 近似，实现复杂 |

#### 直方图的核心缺陷

16 箱在三维只有 4096 个格，而粒子数 $10^5$，**平均每格约 24 个粒子**，信息损失是必然的。

加箱数的改善有限：

| 箱数 | 底噪 | 量化占比 |
|---:|---:|---:|
| 16 | 0.0455 | 94% |
| 24 | 0.0418 | 92% |
| 32 | 0.0394 | 89% |

---

### A3.3 全量不抽样会否使 $W_2$ 更小：会，且已外推

用 `exp9` 的实测数据（$m=1000,2000,3000,4000$）拟合

$$
W_2^2(m)=a+b\,m^{-2/3},
$$

得到 $a=0.004597$，$b=2.8133$。拟合优度：

| $m$ | 实测 | 拟合 |
|---:|---:|---:|
| 1,000 | 0.18050 | 0.18092 |
| 2,000 | 0.15078 | 0.14940 |
| 3,000 | 0.13435 | 0.13462 |
| 4,000 | 0.12478 | 0.12555 |

四个点误差均 $<1\%$。外推：

| $m$ | 外推 $W_2$ | 相对 $m{=}3000$ |
|---:|---:|---:|
| 5,000 | 0.1192 | −11% |
| 10,000 | 0.1032 | −23% |
| 20,000 | 0.0917 | −32% |
| 50,000 | 0.0817 | −39% |
| **100,000（全量）** | **0.0768** | **−43%** |
| $m\to\infty$ | 0.0678 | — |

**结论：全量计算会使 $W_2$ 显著变小（$0.1344\to0.0768$，降 43%）。**

**但这不是模型变好，而是度量变"严"**——全量消除了子采样引入的额外噪声。

#### 代价

| $m$ | 内存（float64）| 单次 OT | 143 格总计 |
|---:|---:|---:|---:|
| 4,000 | 0.12 GiB | 0.08 min | 0.2 h |
| 10,000 | 0.75 GiB | ~1.3 min | 3 h |
| **30,000** | **6.7 GiB** | **~36 min** | **85 h** |
| **100,000** | **74.5 GiB** | **~21 h** | **3057 h** |

$m=30000$ 时内存（6.7 GiB）在 32 GB 机器上可行，但 143 格需 85 小时。$m=100000$ 内存不足，且需约 3057 小时（4 个月）。

### A3.4 可行的替代方案（有文献依据）

| 方法 | 原理 | 偏差 | 代表性文献 |
|---|---|---|---|
| **Multiscale OT** | 先在簇层面解 OT，再在簇内解 | 近似，是收敛下界 | Mérigot 2011 |
| **Sinkhorn（熵正则）** | GPU 并行，分块计算 | 有偏，$\varepsilon\to0$ 时收敛 | Genevay et al. 2018 |
| **神经对偶求解** | 用网络参数化 Kantorovich 势 | 有偏，可扩展到百万点 | Makkuva et al. 2020（W2GN）|
| Sliced + 方差缩减 | 多方向平均 | **是下界，不是 $W_2$** | Nadjahi et al. 2020 |
| 重要性采样 | 按密度重采样 | 取决于设计 | 通用 |

#### 针对本项目的三条建议

**（1）Multiscale OT（Mérigot 2011）**

先把点云聚成 $K$ 个簇（如 $K=1000$），在簇层面解 OT，再在簇内解。复杂度降至 $O(K^3+NK)$，$10^5$ 点可达，且严格下界收敛到真 $W_2$。代价：实现复杂，仍是近似。

**（2）Sinkhorn 在 GPU 上做全量**

复杂度 $O(N^2/\varepsilon^2)$，但高度并行；$10^{10}$ 元素的矩阵可分块计算，无需一次性驻留内存。Genevay et al. (2018) 证明 Sinkhorn 散度是 $W_2^2$ 的一致估计。代价：正则化偏差，须报告 $\varepsilon$。

**（3）本项目最经济：接受子采样，用拟合外推**

既然 $W_2^2(m)=a+b\,m^{-2/3}$ 四点在 $1\%$ 内吻合，可直接外推到 $m\to\infty$ 得 $0.0678$，无需真算 10 万点。成本约 5 分钟（4 个 $m$ 的实测已完成）。

---

### A3.5 结论与建议

| 用途 | 应采用的口径 |
|---|---|
| 主表（与文献对比）| 16 箱直方图，**不可替换** |
| 判定是否达极限 | 粒子级 $m=3000$，**必须同时报告 $m$** |
| **对齐到全量** | 用 $W_2^2=a+b\,m^{-2/3}$ 外推到 $m\to\infty$（已拟合）|

**直方图在本场景是合理选择，但不是最优**；其致命缺陷（量化占底噪 94%）会使"离极限多远"的判断失真。粒子级的缺陷是子采样，但可通过外推修正。

### A4.1 网络架构：极简 MLP

#### MeanFlow（主方法）

代码位置：`upstream/MF-DeepParticle/deepparticle/training/core.py:86`

```python
class Meanflow(nn.Module):
    def __init__(self, width=64):
        self.net = nn.Sequential(
            nn.Linear(6, width), nn.SELU(),
            nn.Linear(width, width), nn.SELU(),
            nn.Linear(width, width), nn.SELU(),
            nn.Linear(width, 3),
        )
    def forward_logsigma(self, z, r, t, logsigma):
        return self.net(torch.cat((z, t, r, logsigma), dim=-1))
```

| 项 | 值 |
|---|---|
| 结构 | 4 层全连接（3 隐层 + 1 输出层）|
| 输入维度 | 6 = 3（坐标 $z$）+ $t$ + $r$ + $\log_{10}\sigma$ |
| 宽度 | 64 |
| 激活 | **SELU** |
| 输出 | 3（速度场 $u_\theta\in\mathbb R^3$）|
| 参数量 | **9,027** |

**没有卷积、注意力、残差连接或 LayerNorm。** 输入顺序为 `(z, t, r, log10 σ)`，与上游 notebook 一致。

#### 本工作的双参数扩展

唯一改动是输入从 6 维变 7 维（增加 $\log_{10}\mu$）：

```python
nn.Linear(7, 64) -> SELU -> ... -> nn.Linear(64, 3)
```

参数量 9,155。

#### DP 修正器

```python
nn.Linear(4, 64) -> [LayerNorm(64) -> Linear(64,64) -> SiLU -> Linear(64,64)] x 2
                 -> Linear(64, 3)   # 输出层零初始化
```

残差形式：$x_{\text{out}}=x+\alpha\cdot\text{MLP}(x,c)$，每块 $h\leftarrow h+0.2\cdot\text{block}(h)$。

### A4.2 损失函数：两个网络、两种损失

#### MeanFlow —— MeanFlow 恒等式

设 $x_0$ 为目标端（$t=0$）、$x_1$ 为初值端（$t=1$）：

$$
v=x_1-x_0,\qquad z=(1-t)x_0+t\,x_1 .
$$

沿插值轨道的时间导数由 Jacobian-向量积给出：

$$
\frac{du}{dt}=\frac{\partial u_\theta}{\partial z}v+\frac{\partial u_\theta}{\partial t}.
$$

**损失**：

$$
\boxed{
\mathcal L_{\text{MF}}=\mathbb E\left\|u_\theta(z,r,t,c)-\Big[v-(t-r)\frac{du}{dt}\Big]\right\|^2
}
$$

$(t-r)\frac{du}{dt}$ 项使网络学习**区间 $[r,t]$ 上的平均速度**，而非瞬时速度，因而支持一步跳跃。

**代码实现**（`core.py:372`）：

```python
u, derivative = jvp(lambda zz, rr, tt: model.forward_logsigma(zz, rr, tt, condition),
                    (z, r, t), (velocity, torch.zeros_like(r), torch.ones_like(t)))
desired = (velocity - (t - r) * derivative).detach()    # detach 不可省略
loss, _ = meanflow_loss(u - desired)
```

`.detach()` 的必要性：目标项含 $du/dt$（依赖 $\theta$），若不 detach，梯度会经目标回传，等价于对目标求导，训练发散。

**时间对采样**：$r,t$ 由 $\sigma(-0.4+\mathcal N(0,1))$ 经 sigmoid 得到，取 $t=\max$、$r=\min$；**一半样本强制 $r=t$**，此时损失退化为纯速度回归。

#### DP 修正器

$$
\mathcal L_{\text{DP}}=\underbrace{\|x_{\text{refined}}-x_{\text{matched}}\|^2}_{\text{传输}}+\lambda\underbrace{\|x_{\text{refined}}-x_{\text{source}}\|^2}_{\text{残差}},\qquad\lambda=1
$$

$x_{\text{matched}}$ 为用**精确 OT** 重排后的对应点；匹配每 50 步重算（`ot_refresh=50`）。

### A4.3 优化算法与反向传播

**优化器**：Adam。

**梯度传播的特殊性**：损失依赖网络自身的导数 $du/dt$，反向传播需穿过 Jacobian-向量积。`torch.func.jvp` 在前向中同时给出 $u$ 与 $du/dt$，反向时正常反传。**这不是标准监督学习**——损失含网络自身导数。

**学习率演进**（本工作改进）：

| 方案 | 学习率 | 测试 $W_2$ |
|---|---|---:|
| 固定 | $10^{-3}$ | 0.1207 |
| + cosine | $10^{-3}\to10^{-5}$ | 0.1028 |
| **+ warm-up 2%** | $0\to10^{-3}\to10^{-5}$ | **0.0978** |

warm-up 作用：前 2% 步数从 0 线性升至 $10^{-3}$，避免初期大步长破坏随机初始化。

### A4.4 「两步」的确切含义：需要重要修正

#### 用户的表述

> 先用 MeanFlow 把高斯分布输出成中间分布，再用 DP 以该中间分布为输入训练修正器。

#### 实际实现

**「两步」指 MeanFlow 自己走两段，与 DP 无关。**

采样调度（`ks_workflows.py:488`）：

```python
schedule = [[1., .5], [.5, 0.]]
```

即

$$
x_1 \xrightarrow{\ \text{区间}[0.5,1]\ } x_{0.5} \xrightarrow{\ \text{区间}[0,0.5]\ } x_0
$$

**使用同一个网络、同一份权重，调用两次，每次用不同的时间对 $(r,t)$**：

```python
for t_hi, t_lo in ((1.0, 0.5), (0.5, 0.0)):
    velocity = model(x, r=t_lo, t=t_hi, cond)
    x = x - (t_hi - t_lo) * velocity
```

**本质**：把 $[0,1]$ 拆成两段，每段使用 MeanFlow 的区间平均速度——是对同一条概率流的更精细离散化，**不是两个不同的网络**。

#### MF 与 DP 是并列方法，不是串行两步

| 方法 | 内容 |
|---|---|
| **MF** | 一步生成（核心方法）|
| **DP** | 直接学"初值 → 终值"的确定性映射 |
| **MF + DP** | 先 MF 一步，再用 DP 修正器微调 |
| **MF 两步** | MF 走两段，不使用 DP |

本工作的主体是 **MF 一步**，DP 修正为可选（且推理开销 1.71 倍，不符合一步约束）。两步 MF 仅在最初复现阶段做过（`results/ks3d/multistep/`）。

#### 另一处修正：初始分布不是高斯

实际初始分布是**单位球内均匀分布**：

```python
radius = torch.rand(n, 1).pow(1/3)          # 1/3 次幂保证球内均匀
direction = torch.randn(n, 3)
x0 = radius * direction / ||direction||
```

不是正态分布。这一区别影响流的路径形状。
